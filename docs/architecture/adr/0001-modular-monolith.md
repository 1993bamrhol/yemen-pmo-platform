# ADR-0001: الاستمرار كـ Modular Monolith

- **الحالة:** Accepted
- **التاريخ:** 2026-08-23
- **المرجع:** `../UNIFIED_GOVERNMENT_PORTAL_IA_V1.md`

## السياق

المستودع Spring Boot multi-module ويحتوي حدودًا أولية مثل `identity`, `organization`, `news`, `workflow`, و`reporting`. المنصة تحتاج عشرات الجهات، لكنها لا تملك بعد حجمًا أو استقلال فرق أو متطلبات تشغيل تثبت الحاجة إلى microservices.

## القرار

الاستمرار كتطبيق Spring Boot واحد قابل للنشر، مع وحدات domain واضحة داخل Maven reactor. تتواصل الوحدات عبر interfaces وخدمات تطبيقية داخل العملية، وتملك كل وحدة نماذجها وrepositories الخاصة بها. يمنع الوصول المباشر إلى جداول وحدة أخرى إلا عبر عقد معلن.

## النتائج

### إيجابية

- معاملات واتساق بيانات أبسط خلال بناء Government Directory والصلاحيات.
- نشر ومراقبة وتشغيل أقل تعقيدًا.
- إمكانية استخراج وحدة لاحقًا إذا أثبتت القياسات والحاجة التنظيمية ذلك.

### سلبية

- يلزم انضباط لمنع coupling بين الوحدات.
- أي فشل أو deployment يؤثر في التطبيق الكامل.

## قواعد التنفيذ

- `bootstrap` هو composition root، وليس موضعًا افتراضيًا لكل domain logic.
- `organization` يملك Government Directory.
- `identity` يملك المستخدمين والأدوار والتعيينات النطاقية.
- `workflow` يملك تعريفات وانتقالات مسار العمل.
- لا تُنشأ خدمة مستقلة لكل وزارة أو جهة.
- قرار استخراج microservice يتطلب ADR جديدًا وبيانات تشغيلية.

## البدائل المرفوضة

- تطبيق مستقل لكل جهة: يكرر الكود والحوكمة ويمنع البحث والمحتوى الموحد.
- microservices فورية: تضيف distributed transactions وoperational overhead قبل وجود حاجة مثبتة.
