# Yemen PMO Platform

This repository contains a government portal platform for Yemen with an Arabic-first public frontend and a Java Spring Boot backend.

## Stack
- Java 21
- Spring Boot 3.x
- PostgreSQL
- Flyway
- React / Next.js / TypeScript
- Docker Compose
- Maven

## Local development

1. Copy the environment template:
   - `copy .env.example .env` on Windows
   - or `cp .env.example .env` on Linux/macOS
2. Review the values in `.env` and replace secrets, especially:
   - `POSTGRES_PASSWORD`
   - `SPRING_DATASOURCE_PASSWORD`
   - `SECURITY_JWT_SECRET`
   - `ADMIN_PASSWORD`
   - `APP_CORS_ALLOWED_ORIGINS`
   The JWT secret must be Base64- or Base64URL-encoded and decode to at least 32 random bytes.
3. Start the full stack:
   - `docker compose up --build`
4. Access the app:
   - Frontend: http://localhost:3000
   - Backend API: http://localhost:8080
   - PostgreSQL: localhost:5432

## Initial administrator
- The username defaults to `admin` and can be changed with `ADMIN_USERNAME`.
- There is no default password. Set a strong, unique `ADMIN_PASSWORD` before the first start.
- The password is used only when the administrator is created; changing the environment variable does not reset an existing account.

## Free staging deployment

The repository includes `render.yaml` for the Spring Boot API and `netlify.toml` for the Next.js frontend. Neon supplies the external PostgreSQL database. This combination is suitable for demos and staging, not an official production service.

### 1. Create the Neon database

1. Create a Neon project and database.
2. Open **Connect** in the Neon dashboard and keep the host, database, username, and password available.
3. Build the JDBC value for Render in this form:
   - `jdbc:postgresql://<host>/<database>?sslmode=require`
4. Keep the database credentials private. Do not add them to this repository.

### 2. Deploy the backend on Render

1. In Render, create a new **Blueprint** from this GitHub repository. Render will read `render.yaml` from the repository root.
2. Supply the prompted secret values:
   - `SPRING_DATASOURCE_URL`: the Neon JDBC URL from step 1.
   - `SPRING_DATASOURCE_USERNAME`: the Neon database user.
   - `SPRING_DATASOURCE_PASSWORD`: the Neon database password.
   - `ADMIN_PASSWORD`: a strong, unique initial administrator password.
   - `APP_CORS_ALLOWED_ORIGINS`: use a temporary non-working origin such as `https://placeholder.invalid` until Netlify assigns the final site URL.
3. Wait for the deployment to finish, then confirm:
   - `https://<render-service>.onrender.com/actuator/health`
4. Save the Render service URL for the frontend configuration.

`SECURITY_JWT_SECRET` is generated by Render from the Blueprint and is not stored in Git.

### 3. Deploy the frontend on Netlify

1. Import this GitHub repository into Netlify. The root `netlify.toml` selects the `frontend` directory and its Next.js build.
2. Add these environment variables before deploying:
   - `NEXT_PUBLIC_API_BASE_URL=https://<render-service>.onrender.com`
   - `API_BASE_URL=https://<render-service>.onrender.com`
3. Deploy and save the exact production origin, for example `https://<site-name>.netlify.app` without a trailing slash.

### 4. Complete the CORS link

1. Return to the Render service environment settings.
2. Replace `APP_CORS_ALLOWED_ORIGINS` with the exact Netlify production origin.
3. Redeploy the Render service.
4. Open the Netlify site, submit a support request, and sign in at `/login` with the configured administrator credentials.

If a custom domain is added later, update `APP_CORS_ALLOWED_ORIGINS` to the new exact HTTPS origin. Multiple origins can be supplied as a comma-separated list only when both origins must remain active.

## Production checklist
- Use a strong JWT secret and unique DB credentials.
- Restrict `APP_CORS_ALLOWED_ORIGINS` to the exact deployed frontend origin.
- Keep environment variables outside the source repository.
- Run database migrations automatically through Flyway.
- Terminate TLS at the reverse proxy and expose only the frontend and required API routes.
- Prefer a real Docker-enabled host for final runtime validation.

## Notes
The project was validated locally using backend tests and a frontend production build. Full Docker startup requires an environment with the Docker daemon available.
